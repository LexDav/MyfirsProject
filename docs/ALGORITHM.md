# Алгоритм работы Telegram‑бота «LegalTech ТН ВЭД» (MVP)

## 1. Основные сущности и состояния

### 1.1 Режимы
- **Light** — пошаговый опросник с адаптивной логикой.
- **Expert** — единый ввод описания и (опционально) изображения.

### 1.2 Состояния диалога
1. **Idle** — пользователь не находится в активной сессии.
2. **Collecting** — сбор входных данных (Light или Expert).
3. **Processing** — обработка запроса и расчёт вероятностей.
4. **Result** — показ предложенных кодов и оценок риска.
5. **Cancelled** — сессия завершена командой `/cancel` и очищена.

### 1.3 Основные данные сессии
- `mode` — Light/Expert.
- `input` — описание товара, ответы опросника, изображение.
- `intermediate_candidates` — промежуточные кандидаты и вероятности.
- `final_candidates` — финальные коды и оценки риска.
- `history_entry` — запись в историю (код, дата, описание, вероятность).

## 2. Входные команды и маршрутизация

1. `/start` → приветствие, выбор режима, переход в **Idle**.
2. `/help` → справка по командам, остаётся в текущем состоянии.
3. `/mode` → смена режима, если есть активная сессия — подтверждение отмены.
4. `/classify` → запуск новой сессии, переход в **Collecting**.
5. `/check <код>` → проверка кода, переход в **Processing**.
6. `/history` → чтение истории, остаётся в текущем состоянии.
7. `/cancel` → завершение сессии, очистка данных, переход в **Cancelled** → **Idle**.

## 3. Алгоритм в Light‑режиме

### 3.1 Инициализация
1. Очистить предыдущие ответы (если есть).
2. Перейти к шагу 1 опросника.

### 3.2 Последовательность вопросов (MVP)
1. **Проверка кода**: если пользователь отвечает «Да», запросить код, наименование и изображение (если есть), затем перейти к блоку проверки (`/check`‑логика).
2. **Полное наименование товара**.
3. **Наличие изображения** (запросить файл при ответе «Да»).
4. **Раздел/группа** (список ограниченных групп для MVP).
5. **Назначение товара**.
6. **Материал**.
7. **Форма поставки**.
8. **Упаковка**.
9. **Дополнительная информация**.

### 3.3 Адаптивное ветвление
- После шагов 1–4 выполнить предварительную классификацию.
- Если вероятность ≥ порога (например, 0.85) и 1‑2 кода имеют близкую уверенность, перейти к **Processing** и **Result**.
- Иначе продолжать вопросы 5–9.

## 4. Алгоритм в Expert‑режиме

1. Запросить единое описание товара (назначение, материал, характеристики, комплектация).
2. Принять изображение (если есть).
3. Перейти в **Processing**.

## 5. Обработка запроса (Processing)

### 5.1 Предобработка
- Нормализовать текст (язык, токены, удаление шума).
- Извлечь ключевые сущности (назначение, материал, товарная категория).
- Если есть изображение — извлечь визуальные признаки (опционально, MVP: хранение).

### 5.2 Классификация
1. Получить список кандидатов из справочника ТН ВЭД (ограниченный набор групп для MVP).
2. Рассчитать скоринг для каждого кандидата:
   - совпадения по ключевым словам;
   - уверенность модели NLP;
   - совпадение с известными правилами классификации;
   - наличие/отсутствие критичных признаков (например, материал).
3. Отсортировать кандидаты по итоговой вероятности.

### 5.3 Оценка риска
- `risk = 1 - confidence` с модификаторами:
  - штраф за неполное описание;
  - штраф за отсутствие изображения (если требовалось);
  - бонус за подтверждение ключевых характеристик.
- Категории риска: низкий (≤ 15 %), средний (16–35 %), высокий (> 35 %).

### 5.4 Форматирование результата
Для каждого кандидата вывести:
- Код ТН ВЭД.
- Официальное наименование.
- Вероятность корректности.
- Сообщение об административных рисках.
- Ссылки на нормативные источники (если доступны).

## 6. Проверка имеющегося кода (`/check`)

1. Валидировать формат кода.
2. Поиск в базе актуального классификатора.
3. Если код устарел — предложить актуальные позиции.
4. Вернуть описание, раздел/группу, статус актуальности и краткую оценку риска.

## 7. История запросов

1. После завершения успешной классификации сохранить запись в `history`:
   - `user_id`, дата/время, введённое описание, выбранные коды, вероятность.
2. По команде `/history` вывести список последних запросов (без отменённых сессий).

## 8. Обновление классификатора (cron)

1. По расписанию загрузить обновления (ЕЭК, решения, изменения 2025+).
2. Сравнить с локальной базой, обновить версии кодов.
3. Сохранить журнал обновлений.

## 9. Обработка ошибок и отмена

- При любой команде `/cancel`:
  - очистить временные данные;
  - не сохранять историю;
  - вернуть пользователя в **Idle**.
- Логировать ошибки и исключения в `logs`.

## 10. Выходные критерии (MVP)

1. Пользователь получает 1–3 кода с вероятностями и оценкой риска.
2. Поддерживаются команды `/start`, `/help`, `/mode`, `/classify`, `/check`, `/history`, `/cancel`.
3. История запросов хранится в SQLite.
