# Алгоритм определения кода ТН ВЭД

## Текстовый алгоритм определения кода ТН ВЭД

### Входные данные

Пользователь вводит описание товара (свободным текстом, с характеристиками, назначением, параметрами).

## Шаг 0. Выбор режима работы

Система предлагает пользователю выбрать режим определения кода ТН ВЭД:

- Light-режим (с уточняющими вопросами),
- Expert-режим (без уточняющих вопросов).

## Основной процесс (общий контур)

### Шаг 1. Получить описание товара

Система фиксирует исходные данные от пользователя: описание, доступные документы/характеристики (если переданы).

### Шаг 2. Извлечь признаки товара

Система извлекает (определяет) признаки, необходимые для классификации товара.

- Если выбран Light-режим — система может задавать вопросы, чтобы уточнить признаки.
- Если выбран Expert-режим — система не задаёт вопросы и работает только с тем, что уже предоставлено пользователем.

## Алгоритм (4)

### Шаг 3. Определить код ТН ВЭД по правилам

На основе извлечённых признаков система выбирает наиболее подходящий код ТН ВЭД (с детализацией “до 10 знаков”).

### Шаг 4. Проверить альтернативные коды

Система проверяет, какие ещё коды могут подходить при близких/неполных признаках, и формирует список возможных альтернатив.

### Шаг 5. Сформировать разъяснения по выбранным кодам

Система формирует объяснение выбора:

- почему выбран основной код,
- почему альтернативы менее предпочтительны,
- какие признаки оказались ключевыми.

### Шаг 6. Выдать результат пользователю

Система выводит пользователю:

- наиболее вероятный код,
- альтернативные коды,
- процентную вероятность релевантности для каждого предложенного кода.

## Алгоритм (4)

### Внутренняя логика извлечения признаков (детальный блок)

Извлечение признаков выполняется последовательно по этапам (каждый этап — это “ветка уточнений”):

1. Определение категории товара
   - Например: техника/оборудование, химия, текстиль, продукты питания, сырьё и т.д.
2. Определение функционала товара
   - Что делает товар и какую функцию выполняет (фильтрует, охлаждает, приводит в движение, является упаковкой и т.п.).
3. Определение способа изготовления / степени переработки / принципа работы
   - Как товар изготовлен и обработан (сырьё vs полуфабрикат vs готовое изделие), как он работает (механический/электронный/химический принцип).
4. Определение материала товара
   - Из чего изготовлен товар (и при необходимости — из чего изготовлены его основные части), включая материалы, используемые для его работы/создания.
5. Определение назначения товара
   - Для чего товар предназначен (бытовой/промышленный, медицинский/строительный, для транспорта и т.п.).
6. Определение количественных или качественных параметров товара
   - Количественные: мощность, объём, размер, производительность и т.п.
   - Качественные: особые технические характеристики, форма товара, способ перевозки, если эти параметры влияют на код.

## Алгоритм (4)

На каждом этапе система может:

- задать вопрос для уточнения признака (в Light-режиме),
- либо пропустить этап, если признак не нужен или уже известен.

## Правила применения алгоритма (как “логика пропусков/вопросов”)

Алгоритм применяется гибко — не все этапы обязательны:

- Оценка этапов делается исходя из уже имеющегося набора признаков.
- Если конкретный признак не влияет на выбор кода, то этап его извлечения можно пропустить.
- Вопрос можно не задавать, если признак уже можно извлечь из описания/данных.

Для количественных характеристик система проверяет:

- используется ли этот показатель в структуре кода/описания позиции,
- есть ли порог/диапазон (например “до / более”),
- влияет ли значение на конкретный код.

Качественные критерии — это не “качество товара”, а именно особые тех.характеристики / форма / способ перевозки, если это значимо для классификации.

При выдаче результата система обязана показывать процент релевантности по каждому коду.

В Expert-режиме вопросы не задаются.

## Алгоритм (4)

### Алгоритм в виде “текста-процедуры” (как для ТЗ)

1. Система запрашивает у пользователя описание товара и предлагает выбрать режим: Light или Expert.
2. Система принимает описание товара.
3. Система извлекает признаки товара, проходя по этапам: категория → функционал → изготовление/переработка/принцип → материал → назначение → количественные/качественные параметры.
4. Если выбран Light-режим, то при отсутствии критических признаков система задаёт уточняющие вопросы (и пропускает те признаки, которые не влияют на итоговый код).
5. Если выбран Expert-режим, то система извлекает признаки только из полученного описания без уточняющих вопросов.
6. На основе набора признаков система подбирает наиболее вероятный код ТН ВЭД (до 10 знаков).
7. Система формирует альтернативные коды (если есть конкурирующие ветки классификации).
8. Система формирует разъяснение (какие признаки привели к выбору кода и почему альтернативы менее предпочтительны).
9. Система выводит пользователю основной и альтернативные коды с процентом релевантности каждого варианта.
